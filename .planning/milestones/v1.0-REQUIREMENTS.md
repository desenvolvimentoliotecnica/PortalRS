## v1 Requirements

### Acesso e segurança (ACC)

- [x] **ACC-01**: Apenas usuários com perfil autorizado (gestor/coordenador/gerente ou equivalente parametrizável) podem iniciar solicitação de **aumento de quadro**, limitada ao escopo organizacional da própria área (RN01).

### Formulário e consistência (CMP)

- [x] **CMP-01**: Toda nova solicitação neste fluxo declara tipo/motivo **Aumento de quadro** (RN02).
- [x] **CMP-02**: Quando aumento de quadro, sistema exige **justificativa detalhada** antes de permitir envio (RN03).
- [x] **CMP-03**: Envio só ocorre com **todos os campos obrigatórios** preenchidos (seções equivalentes à história §7.1–7.5); servidor rejeita com erros discriminados (RN04, CA02).
- [x] **CMP-04**: Gestor pode gravar solicitação em **rascunho** sem iniciar triagem (status §8).

### Fluxo no portal até RM (FLX)

- [x] **FLX-01**: Solicitação enviada válida torna‑se **Pendente de Triagem** (ou primeiro status operacional antes de RM, conforme §8 — CA04).
- [x] **FLX-02**: Responsável pela triagem move para **Em Triagem** ou equivalente durante análise.
- [x] **FLX-03**: Triagem pode **devolver ao gestor** com pendências (**Devolvida para Ajustes** — CA06, item 9 do fluxo macro).
- [x] **FLX-04**: Gestor reenvia após correção; ciclo volta à triagem até aprovação.
- [x] **FLX-05**: Após fluxo definido pela empresa (**triagem + aprovação interna**), solicitação aprovada só então pode gerar vínculo com RM (**sem** criar requisição antes dessa decisão interna — RN05).
- [x] **FLX-06**: Estado **Reprovado** encerra com motivação auditável (**Reprovada** — RN14).

### Integração RM — criação (IRM)

- [x] **IRM-01**: Quando solicitado pela transição **Aprovada** no Portal, sistema **cria requisição** no RM com conjunto documentado em §12.1 / integração técnica a definir na fase CA07.
- [x] **IRM-02**: Portal guarda vínculos retornados: **ID interno da solicitação**, **código requisição**, atendimento (se vier), status inicial RM, timestamps, mensagens sucesso/erro (**§12.2 — CA08**).
- [x] **IRM-03**: Em falha, solicitação entra em estado **Erro de integração RM** ou **Pendente de Reprocessamento** com log e possibilidade de **nova tentativa** (RN09, CA09).
- [x] **IRM-04**: Histórico de **todas tentativas** de integração (payload resumido, código HTTP/erro, horário).

### Integração RM — sincronismo (SYN)

- [x] **SYN-01**: Mapeamento **CODSTATUS RM ↔ statuses portal** parametrizável por ambiente/tenant (**§9 observação**) — valores default podem iniciar pela tabela sugerida.
- [x] **SYN-02**: Atualização de status no RM reflete‑se nos **painéis e detalhes** da solicitação no Portal (polling, job ou mecanismo combinado — CA10).
- [x] **SYN-03**: Registrar **última sincronização**, status cru RM e última mensagem erro de sync quando houver (**§12.3**).

### Auditoria (AUD)

- [x] **AUD-01**: Toda mudança relevante (**status**, aprovação, reprovação, devolução, integrações, retentativa) aparece na **timeline** com ator data/hora opcional texto (RN10).

### RH — pós‑RM seleção (SEL)

- [x] **SEL-01**: RH pode avançar para **Em Processo Seletivo** após cenário válido (**CA11**) alinhando com **IRM** quando requisição aprovada RM.
- [x] **SEL-02**: Busca compatíveis no **banco de talentos** filtrável por perfil/competências da solicitação (**CA12**). *Roadmap allowed MVP gap; validate depth in pilot.*
- [x] **SEL-03**: Registro/visualização **sugestões internas** / indicações vinculadas à solicitação (**CA13**).
- [x] **SEL-04**: Conclusões finais (**Contratação Concluída**, **Cancelada**, **Suspensa**, **Encerrada sem Contratação** — RN14, CA14) com coerência de status RM quando aplicável.

### UX (UIT)

- [x] **UIT-01**: Jornada **gestor**: “Abrir nova vaga”, escolha motivo aumento quadro wizards multi‑seções, mesmo conjunto obrigatório validado antes de submit (CA01, CA03).
- [x] **UIT-02**: Jornadas **triagem**, **aprovação** e **RH** separadas por permissão e filtros equivalentes aos status §8 (+ estados erro RM).
